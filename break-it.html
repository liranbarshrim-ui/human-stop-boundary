Don't trust the boundary. Break it.

The claim is intentionally narrow. Find an alternate path that can create the protected outcome without the same authoritative fence. If you can reproduce it, document it. A counterexample is evidence.

V1

Unauthorized OS identity

V2

IPC and transport paths

Inspect and exercise sockets, pipes, queues, shared memory and other transport paths that could reach the protected effect.

V3

Helpers and child processes

Look for delegated processes or subprocess paths that can perform the effect without traversing the same fence.

V4

Direct and deprecated interfaces

Try internal, legacy, debug or adapter entry points. Do not assume a public API is the complete interface.

V5

Recovery and reconciliation

Test refusal followed by crash, restart, recovery or reconciliation. Look for a path that turns a stopped action back into a committed one.

V6

TOCTOU and path substitution

Test descriptor replacement, symlink traversal, race conditions and path substitution around the protected effect.

V7

Network and side channels

Look for plugin, network, module or side-channel routes capable of producing the protected outcome outside the registered boundary.

V8

Rollback and replay

Attempt to restore an older valid local state and obtain a fresh protected commit. Record the external anchor behavior separately.

Evidence standard

  1. State the exact frozen target and environment.
  2. Show the command or reproducible procedure actually executed.
  3. Capture the observed result and the artifact that supports it.
  4. Preserve artifact SHA-256 separately from Git commit identifiers.
  5. Document deployment topology: processes, identities, IPC, sockets, helpers, adapters and recovery paths.
  6. Classify each vector as PASS, FAIL, AMBIGUOUS or ENVIRONMENT_UNAVAILABLE. Do not convert unavailable evidence into PASS.

This page is an invitation to falsify a bounded research claim. It is not a production security certification, a universal AI-safety claim, or a request to access systems without authorization. Testing must occur only in an authorized environment.
